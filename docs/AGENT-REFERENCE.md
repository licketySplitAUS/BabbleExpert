# Expert implementation reference for agents

The found-word cloud receives a validated, ready Babble snapshot matched by the 25-letter grid, with a 1.5-second read deadline. Freeze it per show/reload and pass the same transient words to both overlays; never place words in the hash, telemetry or pack cache. The new Æther/Voice Canvas/Protoplasm/Fibre Tunnel adaptations run from elapsed time and seed, without sensor permissions.

Celebrations: `SelfServeClues/public/celebration-effects.js` owns the self-contained shared canvas renderer. Run `node tools/sync-celebrations.cjs` after editing it to refresh the standalone bundle and Expert's packaged copy; `--check` verifies parity. The sync script accepts the usual sibling checkout layout. Random rewards use the localStorage `lickety-celebration-rotation:v1` shuffled bag: validate version/IDs/uniqueness, persist every draw, show the entire current catalog before reshuffling, and avoid a repeat across the round boundary. Explicit effects, injected overlays and reduced-motion messages must not consume it. The offline preview uses `lickety-celebration-preview-rotation:v1`. Blocked/full storage falls back to page memory, without letting a stale persisted copy rewind failed writes. All shows have synthesized Web Audio cues, with at most 48 active voices in the new sound engine. Audio has its own noise sequence so it cannot change synchronized visuals. Only Expert’s right pane produces sound; overlays explicitly pass `sound:false`. Mute, replay, expiry and destruction must cancel active/queued sounds; reduced-motion messages never create audio. Standalone clues have a Mute button and quietly retry browser audio unlocking on a later interaction. The offline preview starts silently until Play/effect selection or Sound is used. Expert sends the selected effect/seed from its exact packaged celebration URL to both silent overlays. Hosted Clues upgrades older Expert overlays lacking `dataset.effect` through their existing global destroy handle, silently and without browser reports; never replace a selected-effect canvas from 3.6+. Expert now loads the fixed HTTPS `celebration-pack-v1.json` feed lazily through `src/celebration-pack.js`: 512 KiB limit, no redirects, 2.5-second download deadline, six-hour refresh, atomic local cache and bundled fallback. Downloaded functions are syntax-checked without execution in main and run only in sandboxed renderers. The exact packaged show document receives one pack snapshot; both overlays use that snapshot and seed. Navigation/Hide must invalidate pending starts. Older installed clients without this support still need one app update. Catalog changes preserve the unfinished round, playing shuffled additions before the remaining older IDs and dropping removed IDs; browser and Expert profiles keep independent progress. Keep the existing completion/reporting ownership and named fireworks telemetry for compatibility; the optional allowlisted `animation` field identifies the actual show (or `message` for reduced motion) in Discord. `Preview Celebrations.cmd` opens the offline effect chooser; five quick heart clicks launch previews in clues, and Only Expert’s five-click logo launcher sets `chooser=1`; ordinary completion and replay must keep the selector hidden/disabled. Completion draws from the random bag; replay repeats the selected effect and seed without consuming another entry. P only toggles controls. Extend `fireworks.test.js`, `fireworks-main.js` and SelfServeClues' `clues-celebration.test.mjs` for these contracts.

Paths below are relative to the repository root. Read the section relevant to a change; this is not a prerequisite for every edit. Based on source reviewed on 29 October 2026. Existing implementation and tests establish current behaviour; dated plans and transcripts explain decisions but may describe superseded versions.

## Page adapters, synchronization and recovery

- `src/engine.js` is independent of Electron. Keep orchestration and entry classification testable there; `src/pages.js` adapts external page APIs/DOM; `src/app.js` wires windows, events and services.
- Transfers require ready pages and matching 25-letter grids. The original clues puzzle number is unreliable. Include grid identity and page revisions in asynchronous guards; source switches, navigation and a puzzle flip invalidate old work.
- Babble loads saved words asynchronously after the document loads. Preserve `babbleWordListReady`; an initially empty list must not cause every clue word to be replayed. All submission paths share queues. Preserve pacing, duplicate checks and single-flight polling.
- Accepted words are reconciled both ways, including on clue-source changes. A stale display is repaired from Babble's saved word-list endpoint without a page refresh or losing a chat draft. An acknowledgement alone does not prove that displayed words updated.
- Green means confirmed accepted; amber covers duplicates, uncertain delivery and Clues-only results; red requires explicit rejection. Do not classify stale clues or a timeout as an invalid word.
- Legacy bridge calls use `AddBabbleWord`, `GetAllWords` and `showAll`; return values are normalized to strings. Self Serve's reactive refresh must preserve All/On/Off. Older clients still call its compatibility `showAll()`.
- PlayBabble uses Prototype, which overrides `Array.from` and ignores its mapping callback. Injected scripts should use existing compatible DOM-reading patterns such as `Array.prototype.map.call`. Exercise the Prototype regression when changing snapshots.
- `src/page-runtime.js` validates hosts and bounds page calls; calls reject on navigation, crash, destruction or deadline. A timeout does not prove a submission failed or cancel arbitrary JavaScript already running in a page. Check identity/state before further effects; do not blindly replay chat or word submissions.
- `src/page-recovery.js` retries only transient failures of known GET navigations opened by Expert. It does not auto-reload a merely slow/frozen page or replay forms/redirects. Preserve bounded recovery and diagnostics rather than adding generic reload loops.

## Window trust, sessions and layout

- Keep sandboxing/context isolation enabled and Node integration off. Use `src/local-window.js` for local auxiliary-window loading and `trustedLocal` checks: expected webContents, top frame and exact packaged document. Remote-page IPC separately checks the expected pane, top frame and permitted host. A channel name or matching host alone is insufficient.
- `src/preload-*.js` exposes only named feature operations. Remote pages must not receive unrestricted IPC, shell or filesystem access. Validate main-process payloads even when the preload already validates them.
- Babble and Clues share `persist:babble`; Resources uses `persist:resources`. These sessions are separate from the user's normal browser. Preserve HTTPS/non-www Babble canonicalization and cross-game return navigation. Clearing HTTP cache keeps login cookies; site-data reset is destructive and confirmed.
- Native `WebContentsView` surfaces sit above renderer HTML. Preserve layout rectangles, view visibility and zoom after navigation; an HTML loading overlay alone cannot cover a visible native view. Exercise hidden clues, swapped sides, Resources left/right, resizing and non-default zoom when changing layout.
- Single-instance locking/activation belongs in `src/main.js` and `src/startup.js`. Show/focus the main window without relying only on first paint. Auxiliary dialogs should restore the intended parent/focus when closing, not leave the application behind another program.

## Two generations of word-list resources

- `src/resources.js` defines resources. The word-list sources remain `https://licketysplitaus.github.io/Babble/words-N.html`, separate from the Netlify `r46.me` site.
- Current Expert loads `src/ui/word-list.html` and its virtualized viewer. `src/word-list-data.js` fetches hosted HTML as text, extracts `<div class="w">word</div>` data, and validates sorted, unique, lowercase words of the exact requested length. It never executes those hosted scripts.
- Keep strict source-host/path checks, bounded responses and cache validation. Saved lists display immediately; stale lists refresh in the background without replacing words under the pointer. Failed refresh retains good cached data. Arbitrary redirects/sources are not allowed.
- `src/word-list-index.js` supplies pure binary-search/range maths. Render only visible rows plus a buffer; recycle rows without retaining another word's colour, tooltip or pending state. Performance tests assert bounded DOM, not a machine-specific millisecond threshold.
- `src/word-list.js` retains sparse results by puzzle/length. Reset on puzzle change, not on list-size changes. Restore results from the accepted list already read by sync rather than issuing another full DOM scan.
- Resource loads/lookups carry navigation/generation guards. Hide, source changes and newer clue clicks must invalidate stale results. Preserve keyboard priority over hover scrolling, last-clicked anchors for +/- lengths, and N/P/right-click clue navigation without stealing text-entry keystrokes.
- Older released Expert versions still execute hosted list scripts. Changes in Babble's generator must preserve their click/copy/hash protocol as well as the current text parser. Changing current packaged viewer behaviour usually needs no hosted-page change.
- Dice-conflict colouring is advisory. The reference Big Boggle dice are not verified Babble generator rules; never disable words or exclude them from the dictionary based on this classification.

## Local state, reporting and releases

- `src/update-journey.js` persists only versions and update stage, independently of sharing. Diagnostic milestones are consent-controlled and queued: download-ready, later, install-requested, Mac download-opened and running. Confirm running only after the newer local main page loads. Never call an installation request or a Mac link a completed upgrade. Closing Windows with a ready update records installation intent; retain existing save/flush handling.
- Page diagnostics pair slow/freeze and recovery using random incident IDs. Suspend/resume marks in-flight timings interrupted; very late slow callbacks are uncertain too. Omit their elapsed values rather than counting sleep as loading. Detach power listeners on destruction.
- Celebration telemetry uses only bundled/cached/downloaded source and a 12-hex pack revision. Two consecutive pack refresh failures raise a bounded diagnostic; keep fallback silent and retry on a later opening after five minutes. Failed refreshes must not wait the successful six-hour interval.

- Automatic celebrations use the 25-letter grid identity and retain a bounded set of completed grids for the running session. Counter corrections, page/source reloads and changing/missing legacy puzzle numbers must not rearm a completed grid. Opening an already-complete grid consumes its automatic celebration without showing it. Manual previews/replays remain available. Allowlisted `trigger` reporting separates completion, preview, replay and celebration-page reload without sending puzzle data. Match the originating local document's query as well as its path to ignore late starts from a replaced show.

- Celebrations override the system reduced-motion preference by default (`celebrationAnimations: true`), including upgrades without a saved choice. Preserve an explicit saved off choice; off gives a static silent congratulations message regardless of the system preference. Apply the option to Expert's packaged show and both silent overlays; derive overlay motion from the originating show URL so all panes agree. Standalone Clues always animates regardless of browser/OS reduced-motion settings; the shared renderer defaults to animation and uses a static message only when `reducedMotion:true` is explicitly supplied. Expert’s saved off choice remains authoritative for all its panes. This option applies to the next show.
- Automatic update checks wait for the local main window to load. Transient background check failures report only after the bounded retry budget is exhausted; successful retries and closing Expert discard pending check warnings. Manual, download, install and permanent failures remain reportable. Unwrap known HTTP/network codes from GitHubProvider's exception prefix, never from its appended feed XML.
- Periodic page/glow/grid scans pause while the main window is minimized or the machine is suspended. Restore/resume runs a fresh scan without replaying missed timer ticks; in-flight work may finish. Resources enables Chromium background throttling during the pause and restores its responsive rendering setting afterwards. Keep manual submissions and journal suspension boundaries intact. Load optional celebration engines when the first overlay is requested, not at application startup.
- The journal's atomic Babble word observation can be reused once by the same poll's reconciliation. It must match both page revisions, puzzle/grid, operation revision and a one-second freshness limit; otherwise read again. Never reuse it to confirm an individual submission. Idle journal polls update lastSeenAt in memory without scheduling whole-history rewrites; real progress/active time still checkpoint, and suspend/close/update flush the latest observation.
- Startup milestones (local state, main page, Babble ready, Clues ready) stay in memory and appear only in the manually copied support summary. They measure from createApp setup, excluding earlier Electron launch; do not add them to anonymous reporting without reviewing disclosure.

- Settings validation/migration is in `src/settings.js`. Resources starts left; the journal has a one-time default-on migration; hints turn off after the first session. Later user choices persist. The guided tour remains in source but is excluded from packages and menus while reworked.
- `src/progress-journal.js` records local summaries from one atomic Babble snapshot independently of Clues. Preserve partial-tracking labels and monotonic active-time accounting; exclude idle/background, sleep, lock, disconnected and between-launch time. A corrupted journal is preserved and recording blocked until explicit clear; do not silently overwrite it. Save atomically and flush for suspend, shutdown and updates. View-only status uses the puzzle date (or first observed day for undated records) against midnight America/Chicago, including DST: unfinished past puzzles are Incomplete/red, current unfinished puzzles remain In progress, and complete records stay complete. CSV export has been removed. The trusted `journal:copy-summary` operation copies today’s counts, recorded active time, 5×5 letters and found words from a fresh, ready Babble snapshot matched to today’s journal record. Keep the grid and full word list transient, outside journal files and telemetry; do not substitute an old puzzle when today is absent.
- Usage reporting and diagnostics require saved consent. Diagnostics have allowlisted fields, a bounded/expiring queue and deduplication. Do not forward raw exception messages, stacks, page contents, URLs or local paths. `startup.log` is local-only and can contain details that remote reports must exclude.
- Local-window diagnostics may include only a predefined window identifier (Help, What's new, journal, etc.); never a dynamic title or file path. The 3.5.0.1 reliability launcher is local-only and does not change production package metadata.
- Username linking is separate, optional and initially unticked; it never enables usage sharing. Old queued diagnostics must not gain a username link granted after the event. Journal records never enter reports. Explicit contact messages and Datamuse definition lookups are separate user actions, not anonymous usage events.
- Expert owns embedded fireworks/reporting, while standalone clues celebrate independently. Only the first word-list resource per session is reported. Automatic checks/restored preferences must not become artificial user actions.
- `src/updates.js` uses Windows updater install/restart and a macOS DMG download/replacement flow. Do not promise unsigned macOS in-place updates. Before install, wait for engine work and flush state. Manual checks need feedback; avoid duplicate failure reports from updater events plus promise rejection.
- `src/update-prompt.js` formats a compact download/availability prompt from the target release's notes (GitHub HTML or Markdown; select the exact version when given a changelog array). Prefer an `Update highlights` section, otherwise What's New; show at most three short plain-text bullets and omit installer/download boilerplate. Never substitute the running app's bundled highlights for a newer target. Windows Later remains the default/cancel action and still installs on exit. `Preview Update Message.cmd` reads `docs/NEXT_RELEASE_UPDATE_PROMPT_DRAFT.md` without checking or installing updates. Draft wording stays separate from published notes and installed highlights until reviewed. Old installed versions retain their own prompt code until updated.
- Keep three-part package/tag versions and four-part display/build versions consistent. Maintain `RELEASE_NOTES.md`, `src/release-history.json` and `src/update-highlights.json` for a requested release. Highlights acknowledge only on explicit OK, separately from the last-run marker.
- `.github/workflows/build.yml` tests, builds Windows/macOS, verifies hashes/manifests/blockmaps and creates a **draft** tag release with `make_latest: false`. A successful workflow is not proof of a published latest release. After authorized publication, verify both installer assets and automatic-update metadata. Windows checks do not establish native macOS success.

## Focused verification map

For a meaningful bug fix, reproduce the reported failure with the smallest suitable existing fixture/test where practical, then verify the correction. Prefer observable state/events and injectable clocks to fixed delays. Keep assertions about player behaviour or durable contracts; do not expand the test matrix merely to mirror implementation branches. A failing check must be explained or fixed, not hidden by weakening expectations.

Unit files live in `test/unit/`; Electron files in `test/e2e/`. Use the existing `run.js` wrapper for ordinary E2E files; update highlights has `test/e2e/update-highlights-run.js`. Resource fixtures may require `WORD_LIST_DIR` from the Babble checkout.

`npm start` uses live sites and the normal development profile; it is not a fixture-only check. For an isolated interactive review use the launchers documented in `tools/preview/README.md`, or the offline `tools/preview-highlights.cjs` for What's New. Preview profiles retain their own settings; they are separate from installed player data, not necessarily fresh on every launch.

Connectivity/resource diagnostics: `offlineFailure` suppresses explicit disconnected requests and network-coded failures with a negative link hint; DNS, timeout and HTTP errors alone do not prove offline. Keep disk/permission/install defects reportable even while offline. Update diagnostics retain only fixed GitHub service categories, never URLs; online-link hints are inconclusive. `src/resource-sampler.js` uses bounded app-process memory and cumulative CPU deltas normalized to logical machine capacity, with age/window fields, consent gating and suspend resets. Do not infer excessive app usage from total RAM, treat working-set sums as unique memory, or introduce automatic feature disabling without evidence.

Entries has been removed: no session submission list, Entries window, history IPC or restore/retry actions. Keep the ordered submission queue, puzzle guards and personal progress journal independent. Lickety Add retains only one-entry Up Arrow recall; unconfirmed chat stays editable without an automatic resend. Do not reintroduce a full list to support recovery.
